# v3.19.1

v3.19.1 is a patch release following v3.19.0. Most of the surface area is the
governance layer taking on its own shape: a unified `bernstein govern` CLI,
an OTLP ingest boundary, and audit-chain-anchored coverage and compliance
reporting. The rest is key/secret handling, adapters, deterministic context
plumbing, and a set of smaller fixes.

## Governance surface

`bernstein govern` is now the canonical CLI for RBAC/budget verification,
plan generation, OTLP ingestion and governance discovery; `bernstein
governance` forwards to it with a deprecation warning (#5010). An OTLP
ingest boundary anchors spans from unscheduled runs as receipted,
content-addressed audit-chain entries, deduplicating retries and stating its
coverage limits honestly (#4962, #4983, #5024). Also: `PolicyHookRegistry`
anchors one policy-decision record per evaluation (#4912); `bernstein
compliance coverage` reports per-control evidence status (#4978); a paired
endpoint reports run decision-coverage and verifies an uploaded receipt
(#5067); audit reports are now chain-anchored, re-derivable artefacts
(#5077); `bernstein governance plan` diffs a declared posture against the
enumerated environment (#4980); and `bernstein verify pins` checks loaded
plugins and skills against a pinned manifest (#5089).

## Keys, secrets and trust records

The secrets broker now treats an external store as a backend behind one
contract — resolve, mint a short-lived credential, report revocation — so no
secret value copies into Bernstein's own store (#4984). Also: an SSO token
can bind to the X.509-SVID that must present it, never logging the token on
a refused replay (#5030); receipt-signing keys gain a rotation/revocation
lifecycle via a signed key-succession chain (#4211); session revocation
emits a bounded-propagation chain event (#5031); KMS adapters moved to a
subsystem-neutral custody module (#5033); model admission and withdrawal is
now chain-recorded and replay-derived (#5038); model drift against a signed
baseline is a chain-anchored observation (#5041); authority-envelope
verification can pin an externally obtained key (#5064); audit checkpoints
can anchor outside the filesystem via an RFC 3161 timestamp token (#5147);
and an MCP server's tool-set changes are now chain-recorded (#4975).

## Receipts and verification

A signed refusal receipt failed to verify offline in every case — a call
passed an already-built object where the verifier expected to construct its
own, and a broad exception guard swallowed the error; all call sites now
match the contract (#2980). Also: `bernstein volunteer verify-bundle`
re-runs a result bundle's gates in a clean-room worktree against its
attested exit codes and log digests (#3871); diff-comment anchors bind to
target bytes, not line numbers (#3456); `bernstein trace export` emits a
signed TRACE 0.2 record from local state alone (#4667); every adapter kill
returns a structured reap receipt (#5015); `bernstein lineage export-prov`
exports ancestry as W3C PROV-O (#5039); scan results carry the invocation
digest that produced them (#5151); the receipt-on-target freshness check now
covers every entity kind (#5087); and a lineage entry's `sensitivity`
classification propagates to the maximum across its closure (#5042).

## Deterministic context and run records

An opt-in task context pack assembles co-change neighbours, the
test-to-source map, the nearest `AGENTS.md`, and quarantined tests into one
deterministic, content-addressed prompt section (#4522). Also: `bernstein
context manifest` content-addresses a task's declared files (#3366);
`bernstein context segment-prompt` digests the assembled spawn-prompt blocks
(#3455); repository-flow samples persist to a byte-deterministic series
(#4940) feeding a stagnation detector (#4941); `runs report` rows carry
lifecycle state and per-step timings (#5127); and a new lease primitive
claims a named or tag-filtered resource with a TTL (#5128).

## Adapters

New adapters: Kimchi over its ACP transport with session resume (#3100),
Nmap with volatile timestamps normalized out of the transcript (#3618),
garak for adversarial probing (#4839), and Skyvern driving a self-hosted
server with per-task isolation (#4876). Also: `bernstein adapters draft`
drafts a candidate invocation profile from an installed CLI for operator
confirmation (#3763); gptme now wires `max_tokens` through to the process
environment (#4955); and a feed-pinned Trivy scan hashes the database it
actually loaded before scanning (#4961).

## Smaller fixes

Approval gates that timed out with no decision used to resolve as approved;
every path now fails closed (#5051). Tool input and output are now
inspected for secrets on the post-tool hook path as well as pre-tool
(#4992). `bernstein activity` gained `research`, `data`, and `ops`
subgroups alongside browser, each anchoring its result for offline replay
(#4925).

Twelve smaller fixes: `undo --dry-run` previews a task's change set (#2919);
a test module that loses collected cases now fails CI (#4873); the dead
`workload_prediction` module is removed (#4904); a spawn records its
resolved executor identity in the run journal (#4908); Cedar policy parsing
now reads whole multi-line statements and rejects unsupported constructs at
construction (#4913); `bernstein pipeline run` resolves tracker adapters and
records each sweep in the audit chain (#4916); a `null` downgrade reason no
longer renders as the string `None` (#4918); a spawner that cannot create a
worktree falls back to the main directory instead of raising (#4938);
release-notes rotation now deletes consumed fragments without duplicating
them onto the version page (#4947); a worker completion payload can
identify its output by a content digest (#5002); a deployment example now
matches the actual `bernstein worker` CLI (#5048); and a pull-request
description's diff-stat is computed from the branch itself, not a stale
snapshot (#4996).
